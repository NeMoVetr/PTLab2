# Часовой бутик Patek Philippe

Учебное приложение Django: каталог часов Patek Philippe из коллекций Calatrava,
Nautilus, Aquanaut и Complications. Оформление покупки одной единицы,
учёт остатков в PostgreSQL.
Приложение запускается локально.

## Локальный запуск

Требуются Python 3.14+, uv и PostgreSQL. Создайте базу `prog_tech_lab_2`
и заполните локальный `.env` ключами `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`,
`DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST` и `DB_PORT`.


```shell
uv sync --locked
uv run python manage.py migrate
uv run python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Удаление товара каскадно удаляет связанные покупки.
Цены и остатки Patek Philippe в проекте демонстрационные, перед продажей укажите
реальные данные.

Для управления каталогом создайте администратора:

```shell
uv run python manage.py createsuperuser
```

В `/admin/` можно менять описание, цену, остаток и видимость модели.


## Устройство приложения

- `shop/models.py`: товары, покупки, атомарное оформление заказа.
- `shop/forms.py`: `PurchaseForm`, обязательные поля и проверка доступности.
- `shop/views.py`: каталог и оформление через функции представлений.
- `shop/templates/shop/`: страницы с классами Bootstrap 5 и общим шаблоном.
- `shop/migrations/`: схема БД и первоначальные данные.
- `shop/tests/`: тесты моделей, форм, страниц, данных.

Покупка блокирует строку товара через `select_for_update` в транзакции,
повторно проверяет остаток, сохраняет заказ и уменьшает количество на единицу.
Ошибка отменяет всю транзакцию. Товар из URL определяет заказ. После покупки выполняется перенаправление в каталог.

## Тестирование

```shell
uv run python manage.py test --noinput
uv run python manage.py makemigrations --check --dry-run
```

Тесты приложения:

| Файл и класс | Что проверяется | Работа с базой |
| --- | --- | --- |
| `shop/tests/test_models.py` — `ProductPurchaseUnitTests` | Создание покупки и уменьшение остатка; запрет покупки неактивной модели или модели без остатка; строковое представление товара и покупки. | Моки ORM и транзакции, без обращения к тестовой БД. |
| `shop/tests/test_views.py` — `PurchaseFormUnitTests` | Валидация формы при наличии и отсутствии товара, передача данных покупки модели, Bootstrap-классы полей. | Изолированные тесты, без обращения к БД. |
| `shop/tests/test_views.py` — `ViewUnitTests` | Фильтрация и сортировка каталога; GET формы покупки; успешный и неуспешный POST. | Моки запросов к товарам, форм и рендеринга. |
| `shop/tests/test_stock.py` — `StockTests` | Покупка и списание остатка; откат при ошибке; ограничения остатков; формы, каталог и HTTP-сценарии, включая CSRF и недоступные товары. | Интеграционные тесты с тестовой БД Django и клиентом. |

## Результаты и выводы

Unit-тесты изолированно проверяют логику моделей, формы и представлений с помощью
моков. Интеграционные тесты отдельно проверяют взаимодействие приложения с
тестовой БД и HTTP-клиентом, в том числе запрет повторной покупки закончившегося
товара, откат транзакции, экранирование имени и выбор товара по URL.
