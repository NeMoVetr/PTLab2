# Часовой бутик Patek Philippe

Учебное приложение Django: каталог часов Patek Philippe из коллекций Calatrava,
Nautilus, Aquanaut и Complications. Оформление покупки одной единицы,
учёт остатков в PostgreSQL.
Приложение запускается локально.

## Локальный запуск

Требуются Python 3.14+, uv и PostgreSQL. Создайте базу `prog_tech_lab_2`
и заполните локальный `.env` ключами `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`,
`DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST` и `DB_PORT`.


```shell
uv sync --locked
uv run python manage.py migrate
uv run python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Миграция заменит прежний демонстрационный каталог
на часы Patek Philippe. Исторические товары останутся в базе и в админке, но
будут скрыты из каталога; заказы к ним сохранят связи. Цены и остатки Patek
Philippe в проекте демонстрационные, перед продажей укажите реальные данные.
Для управления каталогом создайте администратора:

```shell
uv run python manage.py createsuperuser
```

В `/admin/` можно менять описание, цену, остаток и видимость модели.


## Устройство приложения

- `shop/models.py`: товары, покупки, атомарное оформление заказа.
- `shop/forms.py`: `PurchaseForm`, обязательные поля и проверка доступности.
- `shop/views.py`: каталог и оформление через функции представлений.
- `shop/templates/shop/`: страницы с классами Bootstrap 5 и общим шаблоном.
- `shop/migrations/`: схема БД и первоначальные данные.
- `shop/tests/`: тесты моделей, форм, страниц, данных и конкурентных покупок.

Покупка блокирует строку товара через `select_for_update` в транзакции,
повторно проверяет остаток, сохраняет заказ и уменьшает количество на единицу.
Ошибка отменяет всю транзакцию. Товар из URL определяет заказ; клиент не может
подменить его скрытым полем. После покупки выполняется перенаправление в каталог,
поэтому обновление страницы не повторяет отправленный POST.

## Тестирование

```shell
uv run python manage.py test --noinput
uv run python manage.py makemigrations --check --dry-run
```

GitHub Actions запускает автоматические проверки при push в `master`,
`feature/**` и при pull request: устанавливает PostgreSQL на runner,
зависимости из `uv.lock`, проверяет миграции и выполняет все тесты.
Конфигурация находится в `.github/workflows/ci.yml`.

## Результаты и выводы

Разработка выполняется в `feature/patek-philippe`, созданной от `master`,
с отдельными коммитами функциональности и автоматического тестирования.
После успешных проверок ветка объединяется с `master`.

Модульные тесты проверяют, что покупка уменьшает остаток, отсутствующий товар
нельзя заказать, прежние модели скрыты из каталога, а история заказов сохраняется.
Проверяются также ошибки формы, транзакционный откат, параллельные покупки,
CSRF, экранирование имени и подмена идентификатора. Два клиента не могут купить
последнюю единицу одновременно.
