# Магазин предметов роскоши

Учебное приложение Django: каталог часов, сумок, украшений и аксессуаров,
оформление покупки одной единицы товара, учёт остатков в PostgreSQL.
Приложение запускается локально. Лицензия — [MIT](LICENSE): допускает
использование, изменение и распространение кода с сохранением текста лицензии.

## Локальный запуск

Требуются Python 3.14+, uv и PostgreSQL. Создайте базу `prog_tech_lab_2`,
скопируйте `.env.example` в `.env`, задайте свой секретный ключ и пароль БД.
Переменные окружения процесса имеют приоритет над `.env`.

```shell
uv sync --locked
uv run python manage.py migrate
uv run python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Миграция `0003` один раз добавляет четыре
примерных товара. Цены и характеристики демонстрационные.
Для управления каталогом создайте администратора:

```shell
uv run python manage.py createsuperuser
```

В `/admin/` можно менять описание, цену и остаток. Остаток ранее существовавших
товаров после миграции равен нулю: его необходимо указать по фактическому наличию.
Файл `products.yaml` — пример для отдельной учебной базы; не загружайте его
повторно в рабочую базу, чтобы не восстановить проданные остатки.

## Устройство приложения

- `shop/models.py`: товары, покупки, атомарное оформление заказа.
- `shop/forms.py`: `PurchaseForm`, обязательные поля и проверка доступности.
- `shop/views.py`: каталог и оформление через функции представлений.
- `shop/templates/shop/`: страницы с классами Bootstrap 5 и общим шаблоном.
- `shop/migrations/`: схема БД и первоначальные данные.
- `shop/tests/`: тесты моделей, форм, страниц, данных и конкурентных покупок.

Покупка блокирует строку товара через `select_for_update` в транзакции,
повторно проверяет остаток, сохраняет заказ и уменьшает количество на единицу.
Ошибка отменяет всю транзакцию. Товар из URL определяет заказ; клиент не может
подменить его скрытым полем. После покупки выполняется перенаправление в каталог,
поэтому обновление страницы не повторяет отправленный POST.

Стиль форм и представлений ориентирован на
[Web-sleep-app](https://github.com/NeMoVetr/Web-sleep-app): отдельные `ModelForm`,
валидация и функции представлений. Bootstrap подключён через CDN в `base.html`
и действует на обеих страницах. Для загрузки Bootstrap нужен доступ к интернету.

## Тестирование

```shell
uv run python manage.py test --noinput
uv run python manage.py makemigrations --check --dry-run
```

Для тестов PostgreSQL-пользователь должен иметь право создания тестовой БД.
Тестовая база создаётся отдельно от основной и удаляется после запуска.
Конкурентный тест использует два отдельных подключения PostgreSQL
и проверяет покупку последней единицы.

GitHub Actions запускает автоматические проверки при push в `master`,
`feature/**` и при pull request: устанавливает PostgreSQL на runner,
зависимости из `uv.lock`, проверяет миграции и выполняет все тесты.
Конфигурация находится в `.github/workflows/ci.yml`.

## Результаты и выводы

Разработка выполняется в `feature/luxury-shop`, созданной от `master`,
с отдельными коммитами функциональности и автоматического тестирования.
После успешных проверок ветка объединяется с `master`.

Локально на PostgreSQL успешно выполнен 31 тест. Проверки подтверждают,
что покупка уменьшает остаток, отсутствующий товар нельзя заказать,
неверная форма не меняет БД, ошибка сохранения отменяет заказ, а два клиента
не могут купить последнюю единицу одновременно. Проверяются также CSRF,
экранирование имени, неизвестные товары, подмена идентификатора,
сохранение введённых данных при ошибке и первоначальное наполнение каталога.

Вывод: отключённой кнопки недостаточно для контроля остатков;
правило должно проверяться в транзакции на сервере. Отдельная форма упрощает
валидацию и тестирование, миграция данных воспроизводимо добавляет каталог,
а автоматические проверки помогают выявлять ошибки перед слиянием веток.
По уточнённому заданию используется только локальный запуск приложения.
